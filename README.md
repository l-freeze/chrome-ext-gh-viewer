# Artifact & Issue Manager for GitHub

アクセスできる全リポジトリの GitHub Actions アーティファクトを一覧・ダウンロード・削除し、Issue を Projects に関係なく横断表示する Chrome 拡張機能です。

- 所有者（自分のアカウント・Organization）をチェックで選び、そのリポジトリだけを対象にできます
- 古い・大きいアーティファクトを絞り込み、まとめて削除またはダウンロードできます（削除は確認つき）
- Actions のキャッシュを全リポジトリ横断で一覧し、PR のキャッシュや使われていないキャッシュをまとめて削除できます（削除は確認つき）
- 古い実行履歴を、作成日・結果・ワークフロー名で全リポジトリから検索し、リポジトリ単位で選んでまとめて削除できます（ログとアーティファクトも削除されます。削除は確認つき）
- ワークフローの一覧と最新の実行を表示し、手動実行（`workflow_dispatch`）できます。入力項目はワークフローの定義に合わせて入力欄・プルダウン・チェックボックスになり、実行の前に必ず確認の画面を挟みます。実行したものは、自動更新のオン・オフに関係なく、一覧で待機中から完了まで状態を追います（依頼した直後に 1 回、その後は 1 分ごと）
- Issue は所有者ごとに検索し、リポジトリ単位でまとめて表示します（List。Issue の操作はまだありません）
- Projects の項目をプロジェクトごとのカンバンで表示し、カードをドラッグ＆ドロップするかキーボードの ← → で Status を変えられます。Issue と PR は別のプロジェクトへドラッグすると、確認のあとでそのプロジェクトへ移せます（ドラフトは移せません）（Kanban。Issue タブにマウスを合わせると List と Kanban を選べます）。PR とドラフトを表示するかはチェックで切り替えられます。プロジェクトに入っていない Issue は List にだけ表示されます
- Actions のタブの「アーティファクト」パネルで、成果物をリポジトリ → ワークフロー → 実行ごとにまとめて表示し、その場でダウンロードできます（削除は Artifacts のタブで行います）。実行が完了したら、そのリポジトリの成果物を取り直します
- Releases を全リポジトリ横断で新しい順に一覧し（リポジトリごとに最大 100 件）、添付ファイルをその場でダウンロードできます（閲覧とダウンロードのみ）。プレリリースだけ・正式な Release だけにも絞り込めます
- Actions のシークレットと変数を、リポジトリ単位と Environment 単位で全リポジトリ横断に一覧できます（閲覧専用。シークレットは値を読めないので名前と更新日だけ）。追加・変更・削除は GitHub で行います
- シークレットと変数の比較表で、名前ごとに、どのリポジトリ・Environment に設定があるかを行列で見比べられます（Matrix。Secrets & Variables タブにマウスを合わせると List と Matrix を選べます）。Environment に無くてもリポジトリ単位にあるものは「リポジトリの分を使う」と表示し、どちらにも無いところを設定漏れとして色で示します。設定漏れのある名前だけにも絞り込めます。一覧と同じ取得結果を使うので、API の呼び出しは増えません。列になるのは、シークレットか変数が 1 つ以上あるリポジトリと Environment です（Organization のシークレットは含みません）
- ラベルを全リポジトリ横断で並べて比べ、まとめてそろえられます（Labels）。行はラベル（大文字と小文字を区別しない名前）、列はリポジトリで、基準と名前・色・説明が違うところと、ラベルが無いところを色で示します
  - 基準は、名前・色・説明のそれぞれでいちばん多い値です。マスを押すと、そのリポジトリの値を基準にできます
  - ラベルを選び、足りないリポジトリへの追加と、名前（大文字と小文字）・色・説明の統一をまとめて行えます。どちらかだけにもできます
  - 名前の変更もできます（付いている Issue と PR からは外れません）。変更後の名前がすでにあるリポジトリは、GitHub が受け付けないので飛ばします
  - 変更と削除を送るのは、列の見出しでチェックを入れたリポジトリだけです（最初はどれも入っていません。チェックは保存しません）
  - ラベルの削除もできます。削除は 2 段階で確認します。1 段目で、付いているすべての Issue と PR から外れて元に戻らないことと、削除するもの（リポジトリとラベル）の一覧を示し、2 段目で `delete` と入力するまで削除のボタンを押せません。削除できなかったものは、残っているラベルとして示します
  - 変更と削除は、確認してから 1 件ずつ送り、送ったリポジトリだけを取り直します。アーカイブ済みのリポジトリは対象外です
- リポジトリの設定を全リポジトリ横断で並べ、ほかと違うところを色で示します（Repository settings）。公開範囲・既定のブランチ・Issues などの機能・マージの方法・ブランチの自動削除と、既定のブランチの保護（ルールセットを含む）を比べます。最初は違いのある設定だけを表示します
  - トークンの権限で返らない設定は「?」、プランで使えないブランチ保護（無料プランの private リポジトリ）は「N/A」と表示し、違いとは数えません。アーカイブ済みのリポジトリは対象外です
  - 見出しを押すと並べ替えます（昇順 → 降順 → 解除）。複数の列を押すと、押した順に優先します。何も指定しないときと同じ値の中は、リポジトリ名の昇順です。「並べ替えをリセット」で元に戻せます
  - 1 リポジトリあたり 3 回（リポジトリ・既定のブランチ・ブランチのルール）呼びます
  - 各行の「変更」から、公開範囲と既定のブランチを変えられます。公開範囲は 2 段階で確認します（GitHub のドキュメントにある影響の一覧 → リポジトリ名の入力）。既定のブランチは既存のブランチから選び、確認してから変えます。ほかの設定の変更は GitHub で行います
  - 変更には、そのリポジトリの管理者の権限が要ります（Fine-grained PAT では Administration: Read and write。リポジトリの削除と同じ権限です）。権限が無くても、表を見ることはできます
- 開いているタブの情報を自動で取り直します。上部の「自動更新」で切り替えられ、既定はオンです。取り直す間隔は「自動更新」にマウスを合わせると、日・時間・分で表示します（例: 1 日、2 時間 40 分）。オフでも再読み込みボタンはいつでも使えます
  - Issue の List は 1 分ごと、Kanban は 2 分ごと、シークレットと変数・ラベル・リポジトリの設定は 1 日ごと
  - Artifacts・Caches・Releases・Actions は、選んでいるリポジトリの数から間隔を決めます。1 時間あたりの呼び出しを API の上限（5,000 回）の 1 割に収めるように切り上げ、最短 5 分です（例: 100 リポジトリならアーティファクトは 12 分ごと、Actions は 24 分ごと）
  - Actions の実行中のワークフローは、これとは別に 1 分ごとに状態を取り直します
  - ページが見えていない間は止まり、戻ったときに間隔以上たっていればすぐに取り直します。削除の確認中と削除中は取り直しません
- 画面は英語と日本語。ブラウザの言語に合わせ、どちらでもなければ英語になります

## 手動インストール

Chrome ウェブストアには未公開のため、GitHub Actions がビルドした ZIP を手動で読み込みます。

1. このリポジトリの Releases から `master build`（タグ `master-build`）を開き、`chrome-extension.zip` をダウンロードします。`master` に push されるたびに最新のビルドに差し替わります。
2. ZIP を展開し、できたフォルダを消さない場所に置きます。Chrome はこのフォルダから拡張機能を読み込み続けます。
3. Chrome で `chrome://extensions` を開き、右上の「デベロッパー モード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」を押し、展開したフォルダ（`manifest.json` が入っているフォルダ）を選びます。
5. ツールバーの拡張機能アイコンを押すと管理画面が開きます。必要ならピン留めしてください。

このビルドには OAuth App の Client ID が入っていないため、接続方法は Personal Access Token だけです。

### 更新

新しい `chrome-extension.zip` をダウンロードし、手順 2 のフォルダの中身を置き換えてから、`chrome://extensions` で拡張機能の再読み込みボタン（円形の矢印）を押します。

同じフォルダから読み込む限り、設定と登録したトークンは引き継がれます。別のフォルダから読み込むと別の拡張機能として扱われ、設定とトークンは引き継がれません。

## 接続方法

| 方式 | 内容 |
|---|---|
| GitHub でログイン（OAuth Device Flow） | github.com でコードを入力して承認します。ビルド時に OAuth App の Client ID が必要です |
| Personal Access Token | Classic（`repo`, `read:org`, `project`）または Fine-grained（Actions: Read and write、Contents: Read、Issues: Read and write、Members: Read、Environments: Read、Secrets: Read、Variables: Read、Organization の Projects: Read and write）。Fine-grained は所有者ごとに 1 つ追加します |

Fine-grained の Administration: Read and write は、Repository settings で公開範囲と既定のブランチを変えるときだけ使います（使わなければ不要です）。Issues の Write はラベルの追加・変更・削除に使います（読むだけなら Read で足ります）。Contents: Read はワークフローの定義とブランチを読むため、Environments: Read は `environment` 型の入力を選択肢で出すために使います。Environments を読めない場合は自由入力になります。

カンバンには `project` スコープ（Fine-grained では Organization の Projects 権限）が必要です。このスコープを追加する前に GitHub でログインした場合は、一度ログアウトしてログインし直してください。個人アカウントのプロジェクトを Fine-grained PAT で扱えるかは確認できていません。

トークンは `chrome.storage.local` にだけ保存され、`github.com` と `api.github.com` 以外には送信されません。

アーティファクトと Release の添付ファイルは、GitHub の API が署名つきの保存先 URL（Azure の Blob や `release-assets.githubusercontent.com`）へ転送します。拡張機能はトークンを付けて API に頼み、転送先の URL だけを受け取ってから、その URL をトークンなしで Chrome のダウンロードに渡します。別のドメインへ転送するときに Authorization ヘッダーを外すブラウザの仕様を使います。その動きを確かめた Chrome 153 以上が必要です。

拡張機能の権限（`host_permissions`）と、ページの CSP の `connect-src` は、GitHub と上の保存先に限っています。保存先への権限は、転送先の URL を読むために使います。転送のあとはブラウザが `Origin: null` を送り、保存先は CORS の許可を返さないためです。

## 開発

```bash
npm install
```

```bash
npm run dev
```

OAuth を使う場合は、GitHub で OAuth App を登録して Device Flow を有効にし、`.env.local` に Client ID を書きます（Client Secret は不要です）。

```bash
echo "WXT_GITHUB_CLIENT_ID=<your client id>" > .env.local
```

| コマンド | 内容 |
|---|---|
| `npm run build` | `.output/chrome-mv3/` にビルド。`chrome://extensions` の「パッケージ化されていない拡張機能を読み込む」で読み込めます |
| `npm run zip` | `.output/` に配布用の ZIP を作成（CI はこれを Release に置きます） |
| `npm run typecheck` | 型チェック |
| `npm test` | 単体テスト（Vitest） |
| `npm run e2e` | ビルドした拡張機能を Chromium に読み込み、GitHub API を偽の応答に差し替えて画面を操作するテスト（Playwright が必要） |

## 構成

```
src/
  features/      業務の機能（workspace / settings / artifacts / caches / actions / issues / projects）
  integrations/  GitHub という外部サービスとの接続
  infrastructure/ 汎用の技術基盤（HTTP 送信・保存先・ダウンロード）
  lib/           仕組みだけの道具（検証・同時実行・並べ替え・時間）
  composition/   具体的な実装を選んで機能をつなぐ
  ui/            Solid の画面
  entrypoints/   拡張機能の入口（background と管理画面）
tests/           単体テスト（持ち主ごと）
e2e/             拡張機能を読み込んだ E2E テスト
```

境界と依存の向き、機能を足すときの判断は [docs/architecture.md](docs/architecture.md) にまとめています。
