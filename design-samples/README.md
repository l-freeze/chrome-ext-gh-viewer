# デザインサンプル比較（UI/UX デザインスキル）

GitHub Artifact Manager（Chrome 拡張 MV3、素の TypeScript + DOM）のメイン画面（Artifacts タブ）を、4 つの UI デザインスキルの指針にそれぞれ従って作ったモックです。

- データはどのファイルも同じです。オーナー 3 つ（`sora-builds` / `acme-labs` / `my-sideprojects`）、リポジトリ 5 つ、アーティファクト 12 件（期限切れ 3 件を含む）。2 件を選択した状態で開き、一括操作バーと合計サイズが見えています。基準日は 2026-10-30 です。
- どれも単一の HTML で、CSS と JS はインラインです。外部から読み込むのは Google Fonts だけです。ライト/ダークは `prefers-color-scheme` で切り替わり、プレビュー用に「Light / dark」ボタンも付けています。
- 合計値は行データから JS で計算しています。オーナーのチェックや行の選択を変えると、サマリーと一括操作バーが追従します。削除の確認は各スキルが勧める方式で実装しました（インライン確認、モーダル、`<dialog>`）。
- 4 つとも幅 1440px と 420px、ライトとダークでレンダリングし、横スクロールやスクリプトエラーが出ないことを確認済みです。

### 候補にしたが見送ったもの

- **solid-ui-design**（このセッションのスキル）：中身は frontend-design の日本語版に近く、トークン、ライト/ダーク、「操作する画面」の節がある。フレームワーク非依存の部分はそのまま使えるが、SolidJS 前提の記述が多く、方向性が frontend-design のサンプルと重なるため、独立したサンプルは作っていない。
- **dataviz**（このセッションのスキル）：グラフ専用で、配色を検証するスクリプトが付いている。画面全体の設計には使えないが、ストレージ内訳のグラフや KPI 表示を作るときに併用する価値がある。
- **ui-ux-pro-max-solid / impeccable-solid**：本体スキルを SolidJS 向けに補うスキル。今回のプロジェクトは素の DOM なので不要。

## 各サンプルの方向性

| ファイル | 見た目の方向性 |
|---|---|
| `frontend-design.html` | 苔のような灰緑の地に、緑青色のアクセントと Schibsted Grotesk。主役は全アーティファクトをサイズ比で並べた「ストレージマップ」で、選択分と期限切れ（斜線）が一目でわかる。各行には保持期間の残り日数をバーで表示。一括操作は浮いたドック |
| `impeccable.html` | 濃紺のシェル帯にタブ、オーナーのチップ、「選択分 / 総量」のメーターを収め、メーターを署名的な要素にしている。システムフォントで 34px の密な表。削除の確認はバー内でのインライン表示。まだ読み込み中のリポジトリはスケルトン行で示す |
| `ui-ux-pro-max.html` | 典型的な高密度ダッシュボード。240px のフィルターサイドバー、KPI カード 4 枚とリポジトリ別の棒グラフ、36px 行の表。ライトは青と琥珀、ダークは IDE 風の紺に緑。削除はモーダルで確認し、完了はトーストで知らせる |
| `taste-skill.html` | 淡い青灰の L 字フレームの上に白いシートを置き、影を使わない。IBM Plex Sans と Plex Mono（ID と数値だけ）。タイトル直下に「30 日超の 3 件で 622.9 MB（全体の 61%）」という発見の文と「3 件を選択」ボタン。KPI は区切り線で並べた文字。右側に「容量の内訳」の細いバーリスト |

## 推奨

**Impeccable（Operate モード）を主軸にし、taste-skill の `app-screens.md` を表の寸法・数値表記のチェックリストとして併用する**のが最も合うと考えます。

- この製品は「繰り返し使う、密度の高い、削除という破壊的操作を含む管理ツール」です。Impeccable の Operate モードは、慣れた操作、状態の網羅、モーダルよりインライン確認、スケルトン表示を明文化していて、素の DOM でもそのまま実装できます。
- taste-skill は表まわりの規則が最も具体的で、実測値に基づいています（数値の右揃え、ISO 日付、欠損値のダッシュ、ゼブラなし、行 44〜48px）。「画面の問いと発見」という考え方も、ストレージ整理という主な作業にはまります（例：「30 日超の 3 件で 622.9 MB」→「選択」ボタン）。
- UI UX Pro Max は手早く「整った」画面が得られますが、汎用的な SaaS の見た目に寄ります。参照データとして使う程度がよいでしょう（UX ガイドライン #35、#81、#91 など）。
- frontend-design は個性の出し方の参考になります（ストレージマップのような製品固有の要素）。ただ、業務 UI の規則が少ないので、主軸にはしません。

組み合わせ案：画面の骨格と操作は `impeccable.html`。表の細部と KPI の見せ方は `taste-skill.html` から取ります。frontend-design の「ストレージマップ」を、Impeccable でいう唯一の署名的な要素として、サマリー部分に小さく入れることも検討できます。
